# 大屏清晰缩放 + 性能模式

## 需求

- 大屏适配保留。
- `1920×1080 清晰`：沿用整页缩放，文字按屏幕物理分辨率重新栅格化，保持清晰。
- 性能模式：1600×900 / 1366×768 / 1280×720 三档固定低分辨率渲染，再用 CSS 放大铺满窗口。
- 设置后立即作用于已打开的游戏窗口；大屏适配关闭时性能模式不生效。

## 方案

### 启动器设置
- 新增 `config.renderSize`，默认 `1920x1080`。
- 设置面板「大屏适配」下方新增「性能模式」下拉：
  - 1920×1080 清晰
  - 1600×900 平衡
  - 1366×768 流畅
  - 1280×720 极速
- 大屏适配关闭时下拉禁用。
- IPC `set-render-size` 保存并广播 `render-size-update`；`set-fit-large-screen` 广播 `fit-large-screen-update`。

### game.html 缩放
- `renderSize === '1920x1080'`（清晰）：
  - webview 恢复 100% 宽高；
  - 使用 `setZoomFactor(coverScale)` 整页放大，文字按屏幕分辨率重新栅格化，避免发虚；
  - 2K 约 1.375x，4K 2.0x。
- 其他三档（性能）：
  - 渲染宽度 = `max(1020, min(所选宽度, 窗口宽度))`
  - 渲染高度跟随窗口比例（16:10 显示器不会被左右裁切），最低 600
  - 用 CSS `transform: translate(...) scale(...)` 把固定尺寸 webview 放大到容器
  - 文字会随放大变软，换来更低 Flash 绘制量。
- 大屏适配关闭：webview 恢复 100% 宽高、zoom=1，按窗口原生尺寸渲染。
- 窗口 resize、iframe 导航、标签创建、设置变更都会重新应用。

## 缩放结果

| 窗口内容区 | 1920×1080 | 1600×900 | 1366×768 | 1280×720 |
| --- | --- | --- | --- | --- |
| 1920×1036（1K） | 1.000x | 1.200x | 1.406x | 1.500x |
| 2560×1396（2K） | 1.375x（清晰） | 1.600x | 1.874x | 2.000x |
| 3840×2116（4K） | 2.000x（清晰） | 2.400x | 2.811x | 3.000x |

| 文件 | 修改类型 | 说明 |
| --- | --- | --- |
| `main.js` | 修改 | config/renderSize、设置面板、IPC、广播、game-info |
| `game.html` | 修改 | 渲染尺寸、CSS 缩放、设置变更监听 |

## 边界

- 窗口宽度小于所选尺寸时按窗口宽度渲染，避免无意义放大。
- 最低按游戏 1020 宽保护；1280×720 是性能模式最低一档，更小窗口会 downscale。
- 1020×600 为最低渲染宽度；高度跟随窗口比例，16:9 下正好 600，16:10 下约 620，不会左右裁切。
- 1920 清晰模式使用整页 zoom，任何分辨率下都会按屏幕物理分辨率重新栅格化字体，保持清晰；其他三档使用 CSS 放大，字体必然变软。
- 大屏适配关闭时渲染尺寸设置不生效。
- 修改设置立即生效，不需要重开窗口。

## 预期结果

- 1K：1920×1080 原生 1:1，文字清晰。
- 2K/4K 选 1920×1080：文字保持清晰，性能接近旧版大屏适配。
- 2K/4K 选 1600/1366/1280：更流畅，但文字会随放大变软。
- 人多场景可切 1600×900 / 1366×768 / 1280×720 进一步降负载。
