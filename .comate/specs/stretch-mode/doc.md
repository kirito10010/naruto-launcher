# 拉伸模式（全屏适配）功能方案

## 1. 背景与目标

火影忍者Online 最初是围绕 1K 显示器开发的 Flash 页游，游戏原生分辨率固定，画面不随窗口缩放。在 2K/4K 显示器上，即使窗口最大化/全屏，游戏画面也只会按原生分辨率显示（不会放大），无法填满屏幕（“没法全屏”）。

目标：在游戏窗口工具栏新增一个「拉伸」开关，开启后 Flash 游戏画面按窗口尺寸自动拉伸填充；关闭后恢复原始比例。

## 2. 需求场景

工具栏开关提供**两档模式切换**：

- **原生模式**（默认，现有行为）：游戏按原生分辨率显示，窗口放大/全屏时画面不放大。
- **拉伸模式**：游戏画面按窗口尺寸自动拉伸填充，窗口多大就填满多大。

1. 用户进入游戏后，点击工具栏开关在两种模式间切换。
2. 切换到「拉伸模式」后，游戏画面立即按当前窗口尺寸拉伸填充。
3. 用户拖动/最大化/全屏窗口时，画面实时跟随窗口尺寸重新拉伸。
4. 切回「原生模式」，画面恢复原生分辨率显示。
5. 开关状态持久化，下次启动自动恢复（复用现有配置存储）。

## 3. 技术方案

### 3.1 拉伸原理

游戏为固定分辨率 Flash（很可能 `scaleMode = NO_SCALE`），直接改元素宽高不会缩放画面。采用 **CSS `transform: scale(sx, sy)`** 对页面中的 Flash `embed`/`object` 元素做视觉缩放：

- 选取页面中面积最大的 `embed/object`（避开广告等小元素）
- `sx = window.innerWidth / 元素宽度`，`sy = window.innerHeight / 元素高度`
- 元素 `position: fixed; left/top: 0; transform-origin: 0 0; transform: scale(sx, sy)`
- 监听页面 `resize` 事件，窗口尺寸变化时重新计算

### 3.2 注入与移除

通过 webview 的 `executeJavaScript` 注入 JS：

- 开启：注入拉伸逻辑（含 resize 监听 + Flash 元素晚出现时的轮询等待）
- 关闭：清除内联样式、移除 resize 监听

### 3.3 多标签与导航适配

- 切换开关时对当前窗口所有标签的 webview 统一应用/移除。
- webview 页面发生导航（登录 → 游戏、刷新）后会丢失注入样式，在 `did-stop-loading` 时若拉伸开启则重新注入。
- 新建标签的 webview 加载完成后同样按当前状态注入。

### 3.4 状态持久化

复用现有 `window.gameAPI.getConfig/setConfig`（IPC `get-config`/`set-config`，main.js 已通用支持任意 key），key 为 `stretchMode`。main.js 无需改动。

## 4. 受影响文件

| 文件 | 修改类型 | 位置 |
|------|----------|------|
| `game.html` | 修改 | 工具栏 HTML（新增按钮） |
| `game.html` | 修改 | 脚本（状态、注入函数、事件绑定、持久化） |

main.js 无需改动（`get-config`/`set-config` 已通用）。

## 5. 边界条件与异常处理

- Flash 元素尚未创建（页面加载中）：轮询等待，最多 30 秒，找到后立即拉伸。
- 页面有多个 `embed/object`：取面积最大者作为游戏目标。
- 元素尺寸为 0（隐藏标签页）：`sx/sy <= 0` 时跳过，避免非法缩放。
- 关闭拉伸：移除内联样式与 resize 监听，恢复原始布局。
- 持久化 key 不存在时 `getConfig` 返回 `undefined`，视为关闭，不影响启动。

## 6. 预期结果

- 工具栏出现「拉伸」开关，带高亮激活态。
- 开启后游戏画面按窗口实时拉伸填充；关闭后恢复。
- 开关状态跨启动保持。
