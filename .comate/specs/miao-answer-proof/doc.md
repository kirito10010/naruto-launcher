# 喵问答 · 零错误答案推导（1.9.0 内修订）

## 一、目标与硬约束

1. **硬约束：导出的 `answer` 永远不能是错误选项。** 拿不准就留空，绝不猜测。
2. 在此前提下尽量多填答案（NPC 答对、我方答对、历史轮次已确认的答案都算）。
3. 导出 JSON 保持现在的 5 个字段：`question` / `options` / `answer` / `removed` / `image`。

## 二、玩法与协议事实（2026-10-30 抓包 20 题实测）

场地四角各有一只猫，猫脚下的圈对应一个选项。4 个 NPC 和玩家（可能还有其他玩家）在倒计时期间各自站到某个圈里；**倒计时结束时，站在正确圈里的人 +10 分**。所以：

- 谁 +10 分，谁就站对了圈；
- 他站的那个圈 = 本题正确选项。

协议里每道题的消息都带这 4 个固定 NPC 的状态：

```
f7（重复 4 次）= 一个 NPC：
    f1 = NPC ID（固定：11000101 / 11004101 / 11000901 / 11000801）
    f3 = 该 NPC 本题站的圈（= 选项下标）
    f4 = 该 NPC 累计得分
```

玩家的状态走命令 `199684`：

```
上行 f1 = 玩家站的圈（提交的选项下标）
下行 f5 = 玩家本题是否站对（1 对 / 0 错）
```

实测结论（20 题全量校验）：

| 校验项 | 结果 |
| --- | --- |
| 每题 NPC 数量 | 恒为 4 |
| 相邻两题的分数增量 | 只有 0 和 10，没有负数、没有其它值 |
| 得分 +10 的 NPC，它们的 `f3` | 100% 相同 |
| 推导出的答案与「被排除的错误选项」 | 0 次相同（说明推导结果不是错误项） |

也就是说：**增量 +10 = 站在正确圈里，它的 `f3` 就是正确选项**。多个 NPC 站在同一个圈里时，他们会同时 +10、`f3` 也相同，正好互为验证。

活动加成排除错误选项的字段是f8，**可能重复 0～2 次**（无加成 / 排除 1 项 / 排除 2 项），导出时 `removed` 是数组，答案校验也改成「不在这个数组里」。

## 三、答案来源（按可信度排序）

### 来源 A：NPC 得分推导（主力，最多 4 个独立证人）

对比第 N 题的帧和第 N+1 题的帧，同一个 NPC ID 的分数：

- 增量必须是 **恰好 +10**；出现 0、负数或其它值 → 本题不推导。
- 所有 +10 的 NPC，`f3` 必须**完全一致** → 该下标就是正确答案。
- 出现两个不同的 `f3` → 视为冲突，本题丢弃，不输出答案。
- 推导出的选项文本如果等于 `removed`（被排除项）→ 数据异常，丢弃。

### 来源 B：玩家（我）站对圈

- 下行 `f5 === 1`，且我方提交的下标合法、对应文本 ≠ `removed` → 我站的那个圈就是正确选项。
- **启用前提（自检）**：`f5` 的含义必须在本场里被来源 A 验证过——同一题既有 A 结论又有我方提交/标志时，`(提交下标 === A结论) === f5` 必须成立。只要出现一次矛盾，或全场没有可对照的样本，**整场不启用来源 B**。
- 实测：本场只有 1 次上行提交（`199684`），与 A 结论一致，验证通过；但没有更多样本，所以 B 实际只贡献 0～1 题。

### 玩家自己的分数

- 最后一帧 `199686` 会带本轮汇总：`f4 = 角色名`、`f3 = 总分`。本次抓包是「鸣人 / 190 分」，即 19 题正确，与玩家记忆一致。
- 但**每题站了哪个圈没有单独下发**：玩家是靠走位站圈，全程只有 1 个 `199684` 上行包，其余是 109 个移动包（`196611`，只含坐标增量，不含圈号）。因此无法用「我答对的 19 题」反推答案，本轮答案只能来自 NPC 加分推导。

### 来源 C：本地答案库（跨轮次累积）

- 位置：`%APPDATA%\naruto-online-launcher\quiz-answers.json`
- 结构：`{ "题干": "正确答案原文" }`（存文本，因为选项顺序每轮可能不同）
- 写入：只有本轮拿到来源 A 或 B 的题才写入，**永远不会写入猜测**。
- 读取：本轮没推导出来时，如果库里这条答案出现在当前选项里 → 直接填。

### 冲突处理

A 和 B 同时存在但结果不同 → 说明某条规则理解错了，**本题答案留空**，并写日志 `[miao] conflict Qn`。宁可不填，也不能填错。

## 四、最终算法

```
对每道题 N（按帧顺序）：
  ans = null
  # 来源 A（NPC 加分 = 站对圈）
  if N+1 帧存在:
     for 每个 NPC:
        d = score(N+1) - score(N)
        如果 d 不是 0 或 10 → 本题放弃 A
        如果 d == 10 → 收集 f3(N)（它站的圈）
     如果收集到的圈下标只有一个值 x → ansA = x
     如果 x 对应文本 == removed → ansA = null
  # 来源 B（玩家站对圈）
  if 我方本题有提交下标 y 且 f5 == 1:
     ansB = y（y 合法且文本 != removed）
  # 合并
  if ansA != null and ansB != null and ansA != ansB → 留空 + 日志
  else if ansA != null → ans = ansA
  else if ansB != null → ans = ansB
  # 来源 C
  if ans == null: 查本地库，命中且文本在当前选项里 → ans = 该文本
  answer = ans == null ? "" : options[ans]
  如果 answer 非空 → 写入本地库
```

## 六、边界与异常

- 每题只有 1 个 NPC 答对 → 仍然采纳（增量恰好 +10 是充分证据）；但若同一题出现不同下标则丢弃。
- 一场里 NPC 全答错 → 该题留空（或用本地库）。
- **每场最后一题**没有下一帧，无法用 A 推导，只能靠 B 或本地库；若玩家开了两轮，下一轮第一帧可补上（分数是累计的）。
- 答案库文件损坏 → 忽略并按空库处理，不影响导出。
- 题干文本带玩家昵称前缀（【1X提供】），直接作为 key，不做归一化，避免误匹配。
- 选项顺序每轮可能不同 → 库里存文本，命中时按文本在当前选项里定位。

## 七、预期效果（用本次抓包回放）

- 20 题中 **15 题**由 NPC 得分直接推导（零错误）。
- 剩余 5 题（当时 4 个 NPC 全答错 + 最后一道没有下一帧）留空，等待：我方答对、下一轮 NPC 答对、或本地库补全。
- 连续参加几轮后，本地库会覆盖大部分题目，导出越来越完整，且每条答案都有证据来源。

## 八、不做的事

- 不用「排除一个错误项」剩下 3 选 1 去猜。
- 不用原作常识/人工答案硬编码进程序。
- 不在拿不准时输出任何内容。
