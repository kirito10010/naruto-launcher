# 高分辨率界面缩放与托盘菜单 - 完成总结

## 改动内容（main.js）

### 界面缩放
- `DEFAULT_SETTINGS` 新增 `uiScale: 0`（0=自动）。
- 新增 `readSystemDpi()`：同步读取注册表 `AppliedDPI`，缓存，失败回退 96。
- 新增 `getUiScale()`：固定比例优先；自动时按 `max(系统DPI/96, 屏宽/1920)` 向上取 `1 / 1.25 / 1.5 / 1.75 / 2`。
- 新增 `applyUiScaleToWindow()`：设置 zoomFactor、调整内容尺寸，并按工作区和屏幕位置回退；导航完成后补一次 zoomFactor（加载会重置缩放）。
- 启动器按 `360×640×scale` 创建并应用缩放；账号管理窗口按 `360×500` 应用。
- 设置面板"性能模式"下方新增"界面缩放"下拉（自动/100%/125%/150%/200%），改动立即生效并保存。
- `set-config` 对 `uiScale` 做数值校验。

### 托盘菜单
- 原生 `Menu` 菜单改为自绘无边框窗口：
  - 右键托盘弹出，左键仍显示启动器。
  - 尺寸 `180×124×scale`，按托盘图标/光标定位并限制在工作区。
  - 显示启动器 / 新建游戏窗口 / 退出三项，跟随当前主题。
  - blur、Esc、点击项后自动关闭；主进程校验 IPC sender。
- 原退出逻辑抽成 `quitFromTray()` 复用。
- 移除未使用的 `Menu` 导入。

### 不变的部分
- 保留 `force-device-scale-factor=1`，游戏窗口与 Flash 渲染逻辑完全未动。
- 游戏窗口创建参数未修改。

## 验证

- `node --check main.js` 通过。
- 临时 userData 设 `uiScale: 1.5` 启动，Win32 `GetWindowRect` 实测启动器为 `540×960`；截图确认文字与布局同步放大。
- 提取真实 `buildTrayMenuHtml()` 输出，在 1.5 倍窗口下截图，菜单字号、间距、主题正常。
- 自动值在本机（1920×1080 @100%）为 100%，窗口保持 360×640。
- 未打包，版本仍为 2.1.0。
