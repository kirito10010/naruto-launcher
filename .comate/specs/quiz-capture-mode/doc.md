# 新增「题库抓包」模式：导出考官红豆「忍者检测」题目 JSON

## 1. 需求

启动器的「抓包模式」新增一项 **题库抓包（忍者检测）**：

- 抓考官红豆 NPC 里「忍者检测」的题目，退出时导出 **JSON** 文件。
- 每条记录包含：**题目、四个选项、正确选项**。
- **正确选项用选项原文**，不能用 A/B/C/D（同一道题的选项顺序会变）。
- 本次**答错**的题 **不提供**正确选项（`answer` 为空字符串）。

## 2. 协议依据（已用真实抓包验证）

题目不是本地配置，而是服务端下发（`zone.huoying.qq.com:11096`，TEA 加密，36 字节头 + Protobuf）：

| 命令号 | 方向 | 作用 |
| --- | --- | --- |
| `251905` | 服务端 → 客户端 | 开始答题，下发第 1 题 |
| `251906` | 客户端 → 服务端 | **提交答案**：`{1: 题号, 2: 选项下标(0-3)}` |
| `251906` | 服务端 → 客户端 | **作答结果 + 下一题** |
| `251907` | 服务端 → 客户端 | 结算 |

服务端「作答结果 + 下一题」的结构（实测解出来的）：

```
field 1: { 1: 0, 2: "success" }      // 接口结果
field 2: 0 | 1                        // ★ 上一题是否答对（1=对，0=错）
field 3: {                            // 题目对象
   1: "题目文本"
   2: "选项A"  2: "选项B"  2: "选项C"  2: "选项D"    // 固定 4 个
   3: 30                               // 时限（秒）
   4: 剩余题数
   5: 题号/计数
   6: { 1: 1000, 2: 12000 }            // 本题奖励（金币/铜币）
   7: { 1: 累计, 2: 累计 }              // 累计奖励
}
field 4: { 1: 物品id, 2: 数量 } ×2     // 奖励物品
```

**协议里没有「正确选项」字段** —— 服务端只回「上一题对不对」。所以：

- **答对**时：客户端提交的选项下标（上行 `field 2`）就是正确选项 → 取选项原文写进 `answer`。
- **答错**时：正确选项不可知 → `answer` 写空字符串。

正确性判定用响应里的 `field 2`。实测证据（本次抓包 10 题）：
- `field 2` 只有 1 帧为 0（第 3 题「忍者修行系统多少级开放」）；
- 同一位置的累计奖励只涨了 500（其余每题为 1000，满分 10000）；
- 两个独立信号指向同一题，交叉验证一致。

解码示例（本次抓包实际结果，可用作验收基准）：

```
题1  以下哪一种方法可以增加好友度？
     自动增加 / 相互切磋 / 赠送玫瑰花 / 聊天        → 答对，正确选项＝赠送玫瑰花
题2  生存演习最多可以选择多少个忍者来进行闯关？
     20个 / 8个 / 12个 / 10个                      → 答对，正确选项＝12个
题3  忍者修行系统多少级开放？
     30级 / 28级 / 25级 / 2级                       → 答错，answer 为空
...
```

## 3. 方案

### 3.1 新增抓包模式 `quiz`

- `normalizeCaptureMode()` 允许 `'quiz'`（除 `off` / `stats` / `full` 外新增一个）。
- 设置面板「抓包模式」下拉新增 `题库抓包（忍者检测）`。
- 抓包说明弹层补充该模式的步骤。
- net-log 复用现有逻辑：`CAPTURE_MODE !== 'off'` 时就会写 net-log，无需改命令行开关。
- **不需要** CDP 抓包（`capture.initCapture` 仍只在 `full` 时开启）。

### 3.2 退出时启动独立的题库导出子进程

沿用现有 `stats` / `full` 的做法（独立子进程 + 等主进程退出 + netlog 写完）：

```
before-quit:
  CAPTURE_MODE === 'quiz' → spawn(process.execPath, [...appArgs, '--export-quiz', pid], { detached })
```

`main.js` 顶部新增 `--export-quiz` 分支（放在单实例锁之前，与 `--export`/`--dump-capture` 同级），调用 `require('./quiz-export').runQuizExport({ mainPid })`，结束后 `process.exit(0)`。

### 3.3 `quiz-export.js`（新增文件）

复用 `export.js` 已有的零依赖能力（需要在 `export.js` 的 `module.exports` 里补导出 `waitForNetlog` / `frames` / `dec` / `pb`，避免重复实现 TEA 与分帧）：

1. `waitForNetlog()` → 等主进程退出、拿到最新 netlog。
2. `extractGameStream()` → 取 11096 连接（返回 `{ rx, tx }`，**tx 也要用**，答案在上行）。
3. 逐帧解析：
   - `rx` 中 `251905` 的 `field 2`、`251906` 的 `field 3` → 题目对象（题面 + 4 选项）。
   - `rx` 中 `251906` 的 `field 2` → 对错标志（按出现顺序）。
   - `tx` 中 `251906` → `{1: 题号, 2: 选项下标}`（按出现顺序）。
4. **按出现顺序配对**：第 i 个答案 ↔ 第 i 道题；第 i 个标志 = 第 i 个答案的对错。
   （帧里自带的 `题号` 实测有跳号，不能当索引；顺序配对与实测数据完全一致。）
5. 生成记录：
   ```js
   {
     question: "以下哪一种方法可以增加好友度？",
     options: ["自动增加", "相互切磋", "赠送玫瑰花", "聊天"],
     answer: "赠送玫瑰花"        // 答错 / 拿不到对错 / 下标越界 → ""
   }
   ```
6. 按题面去重（同一次抓包里重复出现只留一条，优先保留有 `answer` 的那条）。
7. 写文件并高亮：桌面 `火影题库/忍者检测_<yyyy-MM-dd_HHmmss>.json`，`shell.showItemInFolder()`。

JSON 顶层就是一个数组，`JSON.stringify(list, null, 2)`，UTF-8。

### 3.4 设置面板文案

「抓包模式说明」里新增一段：

> **题库抓包（忍者检测）**：重启后找考官红豆做「忍者检测」，把 10 题答完。
> 关闭游戏窗口后走托盘「退出」，会导出桌面「火影题库/忍者检测_时间.json」。
> 内容：题目、四个选项、正确选项（答错的题正确选项为空）。
> 因为同一题选项顺序会变，正确选项存的是选项原文，不是 ABCD。

## 4. 影响文件

| 文件 | 改动 |
| --- | --- |
| `quiz-export.js` | **新增**：解析 251905/251906、配对答案与对错、写 JSON |
| `export.js` | 只改 `module.exports`：补 `waitForNetlog` / `frames` / `dec` / `pb`（供 quiz-export 复用，不改任何现有逻辑） |
| `main.js` | `normalizeCaptureMode` 加 `quiz`；设置下拉加选项、说明弹层加文案；`before-quit` 加 `quiz` 分支；顶部加 `--export-quiz` 子进程分支；`set-capture-mode` 的提示文案加 `quiz` |
| `package.json` | `files` 加 `quiz-export.js` |

## 5. 边界与异常

| 场景 | 处理 |
| --- | --- |
| 本次没答题 / 没连上游戏 | 写出 `[]` 并提示原因（日志 + 空文件），不报错弹窗 |
| 中途退出，最后一题没等到响应 | 该题 `answer` 为 `""` |
| 答错 | `answer` 为 `""` |
| 同一题在一次抓包里出现两次 | 按题面去重，优先保留有答案的 |
| 选项不足/超过 4 个 | 原样输出（正常协议固定 4 个） |
| 服务端协议变更 | 解析不到就输出空数组，不崩溃 |
| 老配置兼容 | `captureMode` 只存字符串，旧值 `off/stats/full` 不受影响 |

## 6. 预期结果

- 设置里选「题库抓包（忍者检测）」→ 重启 → 做完忍者检测 → 托盘退出 → 桌面出现 JSON。
- JSON 形如：
  ```json
  [
    {
      "question": "以下哪一种方法可以增加好友度？",
      "options": ["自动增加", "相互切磋", "赠送玫瑰花", "聊天"],
      "answer": "赠送玫瑰花"
    },
    {
      "question": "忍者修行系统多少级开放？",
      "options": ["30级", "28级", "25级", "2级"],
      "answer": ""
    }
  ]
  ```
- 原有三种模式（关闭 / 组织统计 / 全量抓包）行为完全不变。
