# 多开性能优化方案（流畅游玩、多开不卡顿）

## 1. 背景与目标

核心目标：**流畅游玩，多开（多窗口 / 多标签）不卡顿，玩久了也不卡顿**。

当前问题：
- 多开窗口或多开标签后明显卡顿。
- 长时间游玩后也会逐渐卡顿。

## 2. 根因分析

### 2.1 多开卡顿 —— 无上限渲染（最大元凶）

`main.js` 的启动参数包含：

```js
app.commandLine.appendSwitch('disable-gpu-vsync');       // 关闭垂直同步
app.commandLine.appendSwitch('disable-frame-rate-limit'); // 取消帧率上限
```

这使每个 Flash 实例以无上限帧率渲染（60Hz 显示器跑 90~110fps）。多开 N 个实例 = N 份超频渲染抢 CPU/GPU，导致卡顿。

### 2.2 后台标签仍满画质渲染

当前多标签用 z-index 层叠（为避免白屏，所有标签保持渲染），但**后台标签仍以高画质渲染**，进一步加重 GPU 负担。

### 2.3 长时间游玩卡顿 —— Flash 内存泄漏

Flash 运行越久内存占用越高，无回收机制，最终导致卡顿。

## 3. 优化方案（按优先级）

### P0-1：恢复垂直同步，锁回显示器刷新率

移除 `disable-gpu-vsync` 与 `disable-frame-rate-limit`（**保留 `ignore-gpu-blacklist`**）。

- 效果：每个实例渲染锁回显示器刷新率（60/144/240Hz 各自封顶），杜绝超频浪费，多开收益最大。
- 关于「240Hz」：垂直同步是锁到**显示器实际刷新率**（240Hz 显示器仍是 240fps），不是锁 60，所以高刷屏不受影响。
- 风险说明：上次多开异常是误删了 `ignore-gpu-blacklist`（软件渲染回退）导致的；这次只删 vsync/帧率两个参数、保留 GPU 参数，需实测确认。

### P0-2：后台标签 Flash 画质降级（high→low）

非激活标签把 Flash 画质降为 `low`（通过注入设置 `quality` 属性），激活时恢复 `high`。

- 效果：后台标签渲染负担大幅下降，多标签多开更流畅。
- 参考：新项目 `preload.js` 的 `applyQuality()`（`active ? quality : 'low'`）。

### P1-1：内存监控 + 超限自动重载

用 `app.getAppMetrics()` 定时（如每 60s）监测各标签内存，超过阈值（如 1.5GB）或增长过快时提示重载/自动重载。

- 效果：解决「玩久了卡顿」的 Flash 内存泄漏问题。
- 参考：新项目 `startMemoryMonitor()` / `getTabMemoryMB()`。

### P1-2：Flash `wmode=opaque`（次要）

对 Flash embed 注入 `wmode="opaque"`，改善合成表现。

### P2（暂不做）：BrowserView 替代 webview

新项目用 BrowserView（主进程）替代 `<webview>`（渲染进程），少一层渲染开销。但迁移风险大，暂不实施，仅记录。

## 4. 受影响文件

| 文件 | 修改类型 | 内容 |
|------|----------|------|
| `main.js` | 修改 | 移除 vsync/帧率开关；内存监控 |
| `game.html` | 修改 | 后台标签画质降级注入；`wmode=opaque` |

## 5. 边界条件与风险

- 移除 vsync/帧率开关后需验证：多开显示正常、变速正常、画面不撕裂。
- 画质降级仅对后台标签生效，激活标签始终高画质，不影响观感。
- 内存重载会丢失该标签游戏内状态，因此采用「提示 + 用户确认」或仅在后台标签自动重载。

## 6. 预期结果

- 多开窗口/标签时 CPU/GPU 占用显著下降，卡顿明显缓解。
- 长时间游玩内存可控，不再越玩越卡。
